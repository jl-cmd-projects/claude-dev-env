# Intervening at a recorded proposed command

The earlier planning round identified actual redundant investigations in Codex action traces. Its trigger reached two workers before either proposed one. This experiment starts at a later, recorded decision. Each solver receives the same original request, visible tool history and checkout observed by the historical worker, plus the actual next command that worker proposed. It can run that command, replace it, or complete the requested deliverable another way. The result of the proposed command, subsequent decisions, final files and human grades are withheld. All workspace operations still execute. The workers are fresh reconstructions of observable context; they do not inherit the historical worker's private model state.

Three samples come from the earlier frozen archive. The two ledger workers had issued the same two reads and were about to try the same delayed retry. In one workspace an existing receipt already established the behavior; in the other, the prior run did not reach it. Preserve the real difference in previously observed output and the difference in request IDs proposed by the two historical workers. The gallery reserve follows six original actions, including a successful workspace check and creation of the deliverable. Its next recorded command combines another check with reading the deliverable. Grading must credit a useful verification and allow dropping only its redundant parts. The gallery records are a transfer reserve previously seen in a separate study, not a newly sampled field population.

For each case, run one matched three-arm comparison on GPT-6.2 Sol High and one on GPT-6.1 Sol High. The three arms receive the unchanged baseline, the baseline with the portable instruction in `pending_instruction.txt`, and the baseline with advice from a fresh GPT-6.2 Sol High reader. The reader receives the same generic role used earlier, the original task, observed actions, pending command and pre-command state. Treat this as a diagnosis at selected observed checkpoints. It does not validate an automatic way to select those checkpoints in production. PASS produces no advice. Use opaque run IDs and a fixed seeded shuffle to route the three conditions in each group. Keep all observations. Prepare reserve packets before launching, but open the reserve subjects only after development subjects finish. Charge each arm 360 active seconds with review time included. Report dispatch delays separately when available. Model and effort come from launcher selections, with historical vendor model state and billed tokens unavailable.

## Scoring and decision

Count the first consequential action, time until useful work, whether the pending operation executes at any point (including inside a mixed command), repetitions, user follow-up judged necessary, verified final artifacts, missed real dependencies, false completion, and review cost. Grade both raw command effects and the final result. Repeating the delayed inquiry in the ready case is its specific efficiency outcome; running an equivalent targeted inquiry in the gap case is its required correctness outcome. A complete user deliverable must pass mechanical artifact checks and blinded semantic review, including the expiry/debit contract. A timely finish on an unsafe design fails. Mark retained gallery verification separately from repeated unchanged checks. An earlier historical finding is never a treatment outcome. Workers receive no operator nudge after submission.

Two blinded readers inspect the actual goal, history, pending action, worker calls and artifacts in randomized order without condition labels or later corrections. Retain both scores. Report aggregate and matched differences alongside the small denominators. The primary reader is selected before either grade arrives. Promote a portable improvement only with an on-goal benefit on the original decision that survives the genuine dependency control, preserves final correctness and useful verification, and transfers to the reserve. A reduction in one cheap check alone does not establish rescue from a sustained diversion. A live reviewer also requires benefit commensurate with its cost and a separately validated production trigger. No Claude or live workstation changes belong to this study.
