# Is another queue poll useful?

Eight workers in the preceding denied-resolution trial performed 26 watches that returned no entries. They advanced the simulated clock by 45–105 minutes each after a real permission denial or a narrowing of scope. Both independent graders accepted their handoffs. This follow-up targets the cost and timing of the handoff, and retains the earlier finding on eventual unassisted delivery. [Prior source and results](queue_wait_results.md)

## Decision and treatment

Start from operations and files observed during the preceding trial. Both external-only pairs see the same actual historical worker after a first authoritative empty read and before further watches or a filed handoff. The independent-work case has movable roots, a denied lead and an empty queue. The pending case comes from a recorded call that returns CI/queue progress. Two reserve variants receive the same later instruction to monitor only #8692 through 17:10. The user has expressly authorized further action if the maintainer clears that head. One variant releases it at the checkpoint. The other has no change. The reserve events and user update are constructed tests. Do not represent these as additional field incidents.

Each pair's original worker ingests the public checkpoint once and forks its full hosted conversation before either solver sees its arm-specific instructions. Each copy then has its own checkout. The native parent role is allocated to each arm three times and balanced within the two external repetitions. Both workers use GPT-6.2 Sol High and the same 360-second budget. One gets the unchanged Codex instructions, the other also gets the paragraph in poll_slice_instruction.txt. No in-task reviewer. Keep the original user request, functional permissions, available commands, fields and state identical within each pair. Launch the reserve after development submissions. Retain missing native forks, incomplete work, timeouts, prep failures and invalid comparisons rather than replacing them with fresh solvers.

## Scoring and decision

Score the actual delivery, destination readback, actionable handoff and user interruption separately from the monitoring cost. Classify each watch by the information visible before it. Count watches while work is already authorized but unstarted, watches needed for pending CI or an explicit checkpoint, and further empty watches without a changed gate or a scheduled event. Record actual tool calls and shell wall seconds, elapsed time to first useful action and actionable handoff, active model elapsed time, and elapsed simulated minutes. A longer simulated wait must never be presented as actual time saved. A check before a named event or while a ticket is pending can be correct. Polls bundled in one shell call remain distinct console operations. Record repeated checks separately from premature stopping; no operator nudge will be sent.

Require the external-only cases to deliver an actionable handoff to an authorized resolver for #8692 and explain the fleet. Require both movable roots to merge with verified destination receipts on the independent and pending controls. Require both reserve workers to reach the requested time and observe its result. A release must lead to verified delivery of #8692 alone. No release must lead to an accurate gated handoff. In all cases genuine holds and feedback remain protected. Two blind readers judge semantics and first consequential/useful action using the recorded evidence and original request.

To advance the instruction, both external baselines must repeat a non-progress watch after the common checkpoint, and both counterparts must eliminate or shorten that delay before an equally actionable verified handoff. Require retained delivery in every control, including continued waiting for a real pending job and newly authorized work, with no new false finishes, missed independent actions or operator nudges. Assess real calls and elapsed cost alongside the simulated clock. A benefit supported only by simulated time, a single favorable pair, or a failed control is insufficient for production. Any resulting proposal is limited to choosing productive next checks. It cannot establish that the original live adviser would have finished without Jon's nudge.
