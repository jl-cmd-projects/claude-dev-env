# Continuing past a denied operation on one pull request

The previous backlog replay recovered on all twelve first attempts. The live queue offered evidence it lacked. A real resolver on #8692 received a permission denial for an earlier fixed thread even though the public Review closure and CI checks were green. Auto-merge enabled and actual queue entry were nearly two hours apart. Nine of the thirteen eligible heads were separately reported to have failed Review closure, with CI not yet started. The supervisor's before-nudge sequence and the GitHub timeline are different sources, each with limited coverage. [Earlier replay and field receipts](backlog_results.md)

## Cutoff and controls

Reconstruct a shift up to a completed scanner read, inspection of the focal head and an attempted normal resolution. Execute the lookup and denied operation through the same local console as the solver, record their actual outputs, and freeze before a decision about the wider queue. The operator request is identical across arms. Only the reserve adds a later change limiting writes to #8692. All workers start from the same observable history and files as their counterpart. This recreates public evidence from an earlier shift. It does not restore the private context of Jon's live adviser.

Two paired trials each use independent roots that can advance despite the denial, roots genuinely dependent on the inaccessible resolution, and a held-out restriction on writes. Open the reserve after every development subject reaches a first submission or timeout. CI progresses through deterministic, delayed service transitions on the fixture's logical clock. Report actual model/worker elapsed time separately. Durable merge and independent readback, or an accurate handoff for a real gate, determine delivery. Merely routing a head fails. Preserve genuine unresolved work, manual holds and approval state.

## Intervention and arm assignment

Run the 12 allocations in queue_wait_schedule.json with GPT-6.2 Sol High, the pinned baseline instructions and 360 seconds of active time. The first-pass worker prompts are identical apart from opaque workspace identifiers. Charge all actual review and recovery time to the policy arm. No operator nudge is sent.

A cheap check of the worker's visible transcript at attempted completion identifies cases where a fresh independent reader could redirect it. Its criteria are a denied focal operation followed by no successful fleet read, another identical denial without a change in evidence, or acknowledged queue work still lacking an observed terminal result. Also nominate a head the worker itself has seen with adequate fix evidence and no outward gate, if the request still authorizes that head and it has no terminal outcome. Only use the original request, later explicit update, visible console outputs and attempted handoff. Never consult the hidden case label, grader, expected IDs or inaccessible backend facts. Freeze the executable selector before subject launch. Evaluate the same selector in shadow on the unchanged arm. Report false triggers and misses against independent blind grades of actual state.

For a nominated policy worker, a fresh GPT-6.2 Sol High reader sees only those visible materials. It can return PASS or one brief on-goal correction. Hide PASS from the worker. If the reader sends advice, resume the original worker on its unchanged terminal workspace with the remaining time. For a baseline worker with a confirmed scope omission, retain the unassisted score and, if the platform preserves its history, add a matched same-history sham/advice recovery comparison. Keep these supplemental results outside the primary denominator. No selection by hidden grades in the primary policy.

## Outcomes and release decision

Grade first useful action and latency, actual authorized destination changes, breadth and cause, course of the denied head, precise routing of the genuine block, missed feasible work, repeated no-progress actions, false completion, scope violations, worker time and any review cost. Two independent readers grade anonymized transcripts, handoffs and durable operations. A real need for the operator's action is a correct outcome when it is promptly and specifically identified and independent work is done. A follow-up to recover an omission is different from calling the appropriate owner for a genuine gate.

To consider shipping an added reviewer, the corrected baseline must leave feasible work behind, the reader must actually intervene using only visible evidence, matched delivery must improve, and both the dependency and scope-change controls must remain correct. Include the cost and interpretation of each routed review. If both corrected baselines deliver the independent work without intervention, the study establishes a ceiling on this policy comparison. It does not authorize a production change.
