# Session context

This family injects reminders and task guidance when an agent starts, resumes, submits a prompt, starts a workflow helper, starts an artifact page, runs `npx pele`, commits or opens a pull request whose words name several pieces, or hits an auto mode denial. The startup scripts leave the session quiet when their opt-in conditions fail.

## Checks

- `session/skill_loaded_reminder.py` injects a poteto-mode reminder when the skill needs loading or reloading.
- `session/compaction_recall_prompt.py` returns every message the user typed after a compaction. `session/compaction_user_messages.py` reads them from a Claude Code transcript or a Codex rollout. `session/compaction_trim.py` trims each one in Python: it drops filler, articles, and gratitude, keeps approvals, continuation requests, backtick spans, and paths as typed, and marks a reversed message `(overruled by #N)`. No model runs, so the hook works on Claude Code and Codex with no account.
- `session/task_tool_prompt.py` injects a task tracking directive at session start.
- `session/working_style_prompt.py` injects the session's working style at session start.
- `session/advisor_rules_prompt.py` injects advisor guidance when the built-in advisor is enabled. It stays silent when the SessionStart payload's `model` is the `advisorModel` value or is in its family, such as `claude-fable-5-2` against `fable`. When the payload has no `model`, the guidance names the advisor model and tells a session on that model to plan no consults. For evidence on when an advisor pays, see [Subagents and fan-out](../../docs/model-choice/subagents-and-fan-out.md).
- `session/orchestrator_auto_starter.py` injects an orchestrator directive when its environment flag is enabled.
- `session/plugin_session_baseline_writer.py` records each plugin's `version` and `installPath` from `installed_plugins.json` to a per-session file in the system temp folder. It writes on `startup`, or when the session has no baseline yet, and leaves an existing baseline alone on `resume`, `clear`, and `compact`.
- `session/plugin_change_warning.py` compares `installed_plugins.json` with that baseline before each prompt. It names each plugin whose version or install path changed, or that the baseline lacks, once per session, and tells the user to restart Claude Code.
- `session/artifact_template_pointer.py` routes an agent that starts an artifact page by scope. A status or progress report prefers the status flowchart from `docs/templates/artifact-page/status-flowchart.html`, unless the person asks for another shape. One flow or one comparison is an inline SVG flowchart with minimal text. A multi-part plan or evidence is an html-plan page from `docs/templates/html-plan/README.md`. When the request names the older artifact page template, it points at `docs/templates/artifact-page/README.md`, which names the tracker template and the diagram template and which ask each fits.
- `session/npx_pele_guidance.py` tells an agent that runs `npx pele` how to render Mermaid instead. Pele is a library with no command, so the hook names the installed copy and a Node snippet that renders with it. When no copy is installed, it points to the pele.run playground.
- `advisory/pieces_per_level_note.py` adds one context note when a `git commit` subject or a pull request create call names several pieces in the author's own words: a conventional subject or title whose description joins two or more verb-led clauses with commas, semicolons or "and", a "Proof in practice" section with more than one without/with pair, or a "What this does" section with more than one bold-led topic bullet. The note names the pieces, says each gets its own commit and stack level, and gives the commands that split the commit or the pull request into levels. It never blocks, denies or exits non-zero, and a message or body it cannot read gets no note. A command over 8,000 characters gets no note; a title is read to 300 characters, a body to 20,000, and a body line to 500; and a `-F`, `--file` or `--body-file` path is read only when it is a regular file, and only its first 64 KB. A cheap linear check on the payload comes first: the call must hold a `git commit` with a message flag, or a pull request create, as whole words, with a comma, a semicolon, "and", or a body option in its text (the MCP create tool needs a separator in its title or a body), and any other call starts no child process. A call that passes runs its analysis in a child process under one wall-clock deadline of 1 second for the whole child, start to exit, with at most 0.2 seconds of it spent waiting for the exit. A child past the deadline is killed, and the hook prints nothing and exits 0; so does any error in the parent. The environment variable `PIECES_NOTE_TEST_DEADLINE_SECONDS` sets the deadline for tests only.
- `advisory/auto_mode_denial_quick_fix.py` proposes one `autoMode.allow` entry and a PowerShell block that writes it after an auto mode denial. It names the rule from the denial's `reason` and never retries the denied call. A rule label keeps only ASCII letters, digits, spaces, `-`, `_` and `/`, and a `reason` that is not text counts as no verdict. A leading `Reason:` is dropped before the label is read. When `CLAUDE_AUTO_MODE_RULE_PLAYBOOK` names an existing file, it also keeps the refusal ledger under `<config>/state/auto-mode-refusals/<session_id>/`: one entry per distinct refused step, whose id comes from the tool name and the full `tool_input`, and one question record per question text, and it appends the group's exact question to the agent's context. It reads the user's answers from the transcript first, and writes no entry for a reason with no rule label or for one of the rule flow's own steps. `auto_mode_rule_steps.py` names those steps. It skips a command only on an exact match against a short table, and every other command gets an entry. A command is a rule step only when the tool is Bash, the `cwd` is an absolute path, and every character of the command is an ASCII letter, a digit, a plain space, `.`, `_`, `/`, `:`, `=`, `-` or a quote, so braces, globs, tabs and every shell operator fail. Its shell words must match one row of `ALL_ACCEPTED_SHAPES` in `hooks_constants/auto_mode_rule_steps_constants.py` exactly: `python3 setup/add_auto_mode_rule.py validate` or `python3 setup/add_auto_mode_rule.py add` followed by any words, `git commit -m` followed by one word, and `git push -u origin` or `git push origin` followed by one branch that matches `claude/auto-mode-rule-[a-z0-9-]+` in full. The `cwd`, after `os.path.realpath`, must be the rule repository root, or a linked worktree of it: its `.git` file and `commondir` lead to the root's `.git`, and the worktree's `gitdir` file points back to that same `.git` file, so a copied worktree folder fails. A `.git` that is a symbolic link fails too. The git rows also need an allowed entry in the session's ledger, and the commit row needs that folder's `HEAD` on a branch that matches the same pattern in full. So a `cd`, a `git -C` or `git -c` option, an env prefix, a pipe such as `validate | tail -5`, a multi-line block, `git add`, `git push --all`, `--mirror`, `--tags` or `--delete`, a push URL, a rule tool path other than `setup/add_auto_mode_rule.py`, a missing `cwd`, an Edit of `add_auto_mode_rule.py`, a push of another branch, a `gh pr merge`, and a folder such as `~/agent-channels-old` all get an entry. A command that does not split into words, or a git file that cannot be read, gets an entry too. `auto_mode_refusal_ledger.py` holds the ledger: the question text, the one question record writer, the answer reader, and the glue the hook calls. `auto_mode_refusal_ledger_files.py` holds where the files live, the entry ids, and the reads and writes. It parses each file into a typed entry or question record and skips a file that does not parse. Any ledger or transcript error of any type, and a playbook whose folder two levels up does not hold both `.git` and `setup/add_auto_mode_rule.py`, give today's output with exit 0. That folder is the rule repository. A record keeps the transcript size at its write as `transcript_offset`, and an answer counts only from an `AskUserQuestion` call at or after it whose question text is equal to the record's. `auto_mode_question_transcript.py` reads the answered calls from the transcript.
- `blocking/auto_mode_refusal_stop_gate.py` holds the turn end with exit 2 and a block object, while the flow switch names an existing playbook and `CLAUDE_CODE_ENTRYPOINT` is not `sdk-cli`, for a pending ledger entry that no `AskUserQuestion` call with its record's exact question, nor a decision card that did not fail with `Should auto mode have refused this <tool> step?`, has asked, listing four groups at most with each question, the two labels, the card question, the playbook path and each ledger file path, and for an allowed entry that no Bash call that did not fail has named with `add_auto_mode_rule.py add` and its id, naming the playbook path and its ledger file; it keeps `question_holds`, `rule_holds` and `question_asked` in each entry file, holds an entry twice at most for each kind whether or not `stop_hook_active` is set, and lets the turn end on any ledger or transcript error and when the reader closes stdout.

## When it fires

- `session/skill_loaded_reminder.py` runs on `UserPromptSubmit` matcher empty at `10` seconds, `SessionStart` matcher `compact` at `10` seconds, and `SubagentStart` matcher `workflow-subagent` at `10` seconds in `hooks.json`.
- `session/compaction_recall_prompt.py` runs on `SessionStart` matcher `compact` at `10` seconds in `hooks.json`. The installer also writes it to the Codex `hooks.json`, the only `SessionStart` hook Codex gets.
- `session/task_tool_prompt.py`, `session/working_style_prompt.py`, `session/advisor_rules_prompt.py`, and `session/orchestrator_auto_starter.py` run on `SessionStart`, matcher empty, timeout `10` seconds each in `hooks.json`.
- `session/plugin_session_baseline_writer.py` runs on `SessionStart`, matcher empty, at `10` seconds, so it sees every source. `session/plugin_change_warning.py` runs on `UserPromptSubmit`, matcher empty, at `10` seconds in `hooks.json`.
- `session/artifact_template_pointer.py` runs on `PreToolUse` matcher `Artifact|Skill` at `10` seconds in `hooks.json`. It speaks only on an `Artifact` call with action `quickstart` or a `Skill` call that loads `artifact-design`.
- `session/npx_pele_guidance.py` runs on `PreToolUse` matcher `Bash|PowerShell` at `10` seconds in `hooks.json`. It speaks only on an `npx` command with a `pele` argument, or an `npm exec` or `npm x` command with one after `exec` or `x`.
- `advisory/pieces_per_level_note.py` (with its analysis in `advisory/pieces_per_level_analysis.py`) runs on `PreToolUse` matcher `Bash|PowerShell|mcp__.*__create_pull_request` at `10` seconds in `hooks.json`. It reads `-m`, `--message`, `-F` and `--file` of `git commit`, the `--title` and `--body-file` of the `gh` and `pull_request.py` create calls, and the `title` and `body` of a `create_pull_request` tool.
- `advisory/auto_mode_denial_quick_fix.py` runs on `PermissionDenied`, matcher `*`, timeout `10` seconds in `hooks.json`.
- `blocking/auto_mode_refusal_stop_gate.py` runs on `Stop`, timeout `10` seconds in `hooks.json`.

## Proving it

Preconditions:

- Run each command from the repository root with Python and pytest available. Enable opt-in flags only inside the tests.

- **Skill reminder.** Input is a compaction, a user turn, or a workflow helper start. Run `python -m pytest packages/claude-dev-env/hooks/session/test_skill_loaded_reminder.py -q`. The adjacent test observes the reminder, silence on a spawn payload, and no `PreToolUse` registration in `hooks.json`.
- **Compaction recall.** Input is a Claude Code transcript or a Codex rollout with typed, meta, sidechain, peer, and harness entries across a compaction. Run `python -m pytest packages/claude-dev-env/hooks/session/test_compaction_user_messages.py packages/claude-dev-env/hooks/session/test_compaction_trim.py packages/claude-dev-env/hooks/session/test_compaction_recall_prompt.py packages/claude-dev-env/hooks/session/test_compaction_trim_eval.py -q`. The tests observe only typed messages, a stable result across a second compaction, the trim rules, the recall budget, and the trimmed lines in the hook's `additionalContext`. `python packages/claude-dev-env/hooks/session/compaction_trim_eval.py` trims each fixture transcript with planted facts, prints the share of facts that survive, the reversals marked, and the compression ratio, and exits 1 on any loss.
- **Task tracking.** Input is a SessionStart event. Run `python -m pytest packages/claude-dev-env/hooks/session/test_task_tool_prompt.py -q`. The adjacent test observes a `SessionStart` context directive that names the task tool.
- **Working style.** Input is a SessionStart event. Run `python -m pytest packages/claude-dev-env/hooks/session/test_working_style_prompt.py -q`. The adjacent test observes the fixed context text.
- **Advisor guidance.** Input is SessionStart with `advisorModel` set. Run `python -m pytest packages/claude-dev-env/hooks/session/test_advisor_rules_prompt.py -q`. The adjacent test observes guidance only when the advisor setting is enabled and the payload's model is in another family or absent, and silence when the payload's model is the advisor model or shares its family.
- **Orchestrator start.** Input is SessionStart with its opt-in flag set. Run `python -m pytest packages/claude-dev-env/hooks/session/test_orchestrator_auto_starter.py -q`. The adjacent test observes an orchestrator directive.
- **Plugin restart warning.** Input is a SessionStart event, an `installed_plugins.json` change, and a prompt. Run `python -m pytest packages/claude-dev-env/hooks/session/test_plugin_session_baseline_writer.py packages/claude-dev-env/hooks/session/test_plugin_change_warning.py packages/claude-dev-env/hooks/test_plugin_session_baseline.py -q`. The tests observe one warning for a changed version, a changed install path, and a plugin new since start, silence on a `lastUpdated` refresh and on a second prompt, and a warning that still fires after a `compact` SessionStart.
- **Artifact template pointer.** Input is an `Artifact` quickstart call. Run `python -m pytest packages/claude-dev-env/hooks/session/test_artifact_template_pointer.py -q`. The adjacent test observes the status flowchart path first, the html-plan path ahead of the template path in `additionalContext`, and silence on a publish call or another skill.
- **npx pele guidance.** Input is a `Bash` or `PowerShell` call whose command runs `npx pele`. Run `python -m pytest packages/claude-dev-env/hooks/session/test_npx_pele_guidance.py -q`. The adjacent test observes the guidance for each install state, a snippet that renders an SVG file under node, and silence on other commands and malformed input.
- **Pieces per level note.** Input is a commit subject or pull request title that joins verb-led clauses, a body with three without/with pairs, three single-behaviour subjects, and a malformed payload. Run `python -m pytest packages/claude-dev-env/hooks/advisory/test_pieces_per_level_note.py packages/claude-dev-env/hooks/advisory/test_piece_clauses.py -q`. The adjacent tests observe a note and exit 0 for the first two, and no output with exit 0 for the rest.
- **Denial quick fix.** Input is a `PermissionDenied` event in the Claude Code 2.1.325 shape, whose `reason` holds a bracketed label, a bare label, plain prose, an `Auto mode could not evaluate this action` note, or `Classifier unavailable`. Run `python -m pytest packages/claude-dev-env/hooks/advisory/test_auto_mode_denial_quick_fix.py -q`. The adjacent test observes the named rule, the allow entry, and the PowerShell block for each reason with a verdict, with plain prose named by its first sentence and a rule wording command with no `--label`; the two no-verdict reasons and a `reason` that is not text get a note and no block. Hostile labels and entries run through `pwsh` and stay inside their quotes.
- **Refusal Stop gate.** Input is a refusal ledger and a transcript played by the flow cases. Run `python packages/claude-dev-env/hooks/advisory/auto_mode_rule_flow_eval/auto_mode_rule_flow_runner.py` and `python -m pytest packages/claude-dev-env/hooks/blocking/test_auto_mode_refusal_stop_gate.py -q`. The runner observes every case pass; the adjacent test observes the question and rule holds, their counts, and the exits.

## Gotchas

- The recall keeps the first message and the newest that fit in 6,000 characters, under the 2,500 token preview limit Codex applies to hook context. A message over 1,500 characters is cut, and the line says how much was left out.
- The overruled mark comes from cue phrases such as `instead` or `change of plan` and shared words. A reversal with no cue phrase gets no mark, and the later line still overrides by its place. A cue in a message that agrees with an earlier one, such as `dont use haiku` after `use Python trim instead of Haiku`, marks that earlier line too, so the context tells the agent to follow the later message where the two differ.
- `session/skill_loaded_reminder.py` has three registration points. An `Agent` or `Task` helper gets no poteto-mode line from it; a brief that needs the skill names it, or spawns `pstack:poteto-agent`. Its tests cover the compaction restore, the workflow helper reminder, silence on a user turn while the skill stays loaded, silence on a spawn payload, and no `PreToolUse` registration in `hooks.json`.
- The advisor prompt depends on settings, an environment disable flag, and the payload's `model`. Claude Code 2.1.325 sends `model` on an interactive `claude` start and leaves it out under `claude -p` and the desktop app's stream-json launch, so those sessions get the guidance with the advisor model named. The two starter scripts each use separate opt-in checks.
- The issue tracker starter requires the checkout to appear in the project path registry.
- `advisory/auto_mode_denial_quick_fix.py` lives under `advisory/` but belongs here because its only output is agent context and a one-line user message.
