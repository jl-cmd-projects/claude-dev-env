# Account broker

`account_broker.py` reads the Claude and Codex account lists, checks each account's session and weekly usage, and chooses an account with room. It does not select a model or sleep. A Codex decision names the `normal` or `luna` tier for the caller.

Claude's main home is `~/.claude`. Its `claude-chain.json` file contains a `chain` list; each entry's `credentials_path` field identifies the credentials file whose parent is that account's home folder. The optional `extra-profiles.json` file in the main home lists additional profile names.

The optional `claude-account-order.json` file in the main home sets the Claude pick priority. It is a JSON list of account names, first choice first, such as `["claude-second", "claude"]`. An entry matches an account's name, its command, or its `claude-<name>` launcher, and `claude` names the main account. A new job goes to the first listed account with room. When no listed account has room, the broker picks the unlisted account with the most room, and it waits when no account has room. A resumed session stays on its bound account while that account has room. A listed name absent from the roster is skipped. Without the file, every job goes to the account with the most room. Edit the file to change the order; the next pick reads it.

Codex uses its configured account list. A broker run that reads `CODEX_ACCOUNT_PROFILES` saves that list to `account-launchers.json`, so a later run without the variable reads the same roster; [Codex accounts](codex-accounts.md) has the details. When no Codex roster is configured, `choose` and `check` read the default Codex home, `CODEX_HOME` or `~/.codex` when it is unset or blank, as the account `default` and apply the same plan rule, so a free, missing, unknown or unlisted plan there gives `wait`. A failed read of that home also gives `wait` with exit 3, and the reason names the failure. A new Codex job goes to an account on a Pro plan before any account on another plan, in any tier, whenever a Pro account can run. The plan comes from the account's meter reply, and `ALL_PRO_PLAN_TYPES` lists the Pro plans: `pro`, `prolite`, and `promax`. Among accounts of the same kind, `normal` comes before `luna`, and the one with the most room wins. A Pro account with no credits and more than 0% and at most 10% of its room left takes `luna`, and it still comes before an account on another plan with room in the `normal` tier. A Pro account with no credits cannot run when one of its windows has no room left, when its meters are unread, when a spent mark on it is still in the future, or, for a caller that passes `--require-tier normal`, when it has 10% or less of its room left; the broker then moves to the next account. The 1% weekly stop and the 20% short-window floor apply to accounts on other plans. A caller that passes `--require-tier normal` takes a Pro account only when it reaches `normal`, and otherwise the account on another paid plan with the most room that does. An account on a free plan (`ALL_FREE_PLAN_TYPES`, `free`) is never chosen, and a `wait` reason names it. Only a plan on the paid list (`ALL_PAID_PLAN_TYPES`: `business`, `edu`, `enterprise`, `plus`, `pro`, `prolite`, `promax`, and `team`) is chosen. An account whose meter reply names no plan, a blank plan, `unknown`, or any other name outside that list is never chosen either, and its `wait` reason says so. An account whose meters could not be read keeps the unread handling below and is not judged by plan. An account with credits, which the meter reply reports as `hasCredits` is `true` with a balance above zero, or `unlimited` is `true`, takes the `normal` tier at any plan room, so a Pro account with credits comes before every account on another plan.

## Commands

```text
python scripts/account_broker.py accounts --product claude
python scripts/account_broker.py choose --product codex
python scripts/account_broker.py choose --product codex --spent account-name:1790000000
python scripts/account_broker.py choose --product codex --require-tier normal
python scripts/account_broker.py choose --product codex --home ~/.codex-profiles/codex-1
python scripts/account_broker.py check --product codex
printf "%s" "prompt" | python scripts/account_broker.py run --product claude --report report.json -- claude --output-format json -p
```

`accounts` prints the roster without reading meters. `choose` prints `decision`, `accounts`, and `state_path`. Each decision contains `action`, `account`, `profile`, `home`, `reason`, `tier`, and `resets_at`. `profile` is the name of the profile whose home the account uses, such as `editor` for a home at `~/.claude-profiles/editor`. It is null for the main account, a Codex account, a home outside the profiles root, a home whose folder name is not a valid profile name such as `main`, and a wait decision. `--spent` takes an account's name or its profile. The account order file matches the name, command, or launcher, and resume affinity stores the command, or the name for an account without one. When a mark is one account's name and another account's profile, the name wins. Every mark is read before the first one is saved, so an unreadable mark saves none. `accounts` and the `choose` account list carry the same `profile` field. A wait decision has no account or home and includes the soonest reset in UTC. An account counts as free at the latest reset of the windows that hold it, and one hour out when one of those windows has no reset time. A failed meter read reuses the account's last good reading when that reading is 30 minutes old or less, and otherwise excludes the account for that choice. `--spent` saves an exclusion until the supplied Unix reset, the account's soonest known meter reset, or one hour when neither is available. A `--spent` name absent from the roster is saved until the supplied Unix reset, or for one hour when no reset is given. A mark splits at its last colon, so an absent name that contains a colon, such as `C:\bin\old.cmd`, takes an explicit reset, such as `C:\bin\old.cmd:1800000000`. While any such mark is still in the future, `choose` waits until the soonest mark and exits 3, and with no Codex roster `--spent default` waits until that mark passes. `default` is the name `choose` gives the Codex home when no roster is configured, so while a Codex roster exists `choose` neither saves a `--spent default` mark nor waits on a stored one. Meter reads younger than 60 seconds are reused.

`--require-tier normal` makes a Codex `choose` or `check` wait unless an account reaches the `normal` tier. `--home <path>` makes either command judge that one Codex home alone. A home on a paid plan with readable meters runs, whatever its room, credits or `CODEX_WEEKLY_FLOOR_DISABLED` setting, and reports the tier its meters allow, or `luna` when none does. A home still gives `wait` when its plan is free, missing, blank, unknown or unlisted, when its meters are unread, when it does not reach a required tier such as the one `--require-tier normal` sets, and when a spent mark saved for the roster account with that home, by `run` or `choose --spent`, is still in the future, until that mark's reset. A roster account with that home keeps its name, so its mark holds the home. Any other home reads as an account named for its folder, and a mark is keyed by product, account name and home. So a mark saved for the no-roster default account, named `default`, does not hold `--home <that home>` unless the folder of that home is also named `default`, and a mark saved for an account outside the roster never holds a `--home` answer. After an account leaves the roster, a mark saved while it was in the roster still holds `--home <its home>` only when the account's name equals the name of its resolved home folder. A roster account `Alpha` whose home folder is `alpha`, or whose home folder is a junction to a folder with another name, no longer holds `--home <its home>` once it leaves the roster. The broker refuses `--home` for the Claude product and with `--spent`. `check` prints nothing and exits 3 while every account is below its floor. `run` sets `CLAUDE_CONFIG_DIR` or `CODEX_HOME` for each attempt. A Claude job also starts without the parent session's variables, such as `CLAUDE_CODE_SESSION_ID` and `CLAUDECODE`, so a child started from inside a Claude Code session runs as its own session. `ALL_PARENT_CLAUDE_SESSION_VARIABLES` lists them. It replays the same stdin bytes when a usage limit, start failure, or sign-in failure leads to another account. Send the prompt on stdin. When the command resolves to a `.cmd` or `.bat` file, the broker refuses an argument that holds a cmd.exe metacharacter and records `start_failed`. It writes the command's stdout to stdout and diagnostics to stderr. A resumed Claude session uses the account bound to its session when that account has room.

The broker stores cached meters, spent marks, and Claude session bindings in one JSON file under `~/.claude/account-broker`. Every broker process for the same user reads that file, so a spent mark pauses that account for every job. A write holds an exclusive lock on the sibling `state.json.lock`, re-reads the file, merges, and swaps in a sibling temporary file with `os.replace`. The merge keeps the latest reset for each spent mark and the newest meter read for each account.

## Exit codes and report

| Code | Meaning |
| --- | --- |
| `0` | `choose` or `check` found an account, or the job exited successfully. |
| `3` | No account clears its floor. The decision includes `resets_at`. |
| `4` | A Claude job stopped with `advisor_blocked`, or every Claude account was unusable: each had no token or was signed out. |
| `127` | A Codex job timed out, its command could not start while no Codex roster is configured, or the command could not start on any account in the roster. |
| Other command code | `run` returns the command's exit code after a served response. |

`run` writes a JSON report with `product`, `command`, `events`, and `final_decision`. A wait report has `final_decision.action` equal to `wait` and a UTC `final_decision.resets_at`.
