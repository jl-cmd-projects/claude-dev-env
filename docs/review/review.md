# Review rules

Review supported behavior and the changed repository contract.
Current repository instructions override stale hosted copies.
An intentional contract change is not a defect because an older rule differs.

Report a reachable caller, supported input, and observable failure for each defect.
Check command flags, environment, pipeline, and executable path before calling a command read-only.
Use deployment and trust-boundary evidence for security and atomicity findings.
Separate coverage advice from a demonstrated defect.
Report a new or changed context file that passes the `context-budget` lint and still carries detail a pointer to a reference file should hold.

Bind delayed events, cancellation, and review evidence to the full candidate head and run.
Completed review can contain findings. A resolved thread, driver reply, timeout, or quota notice does not prove repair or a clean review.
Only verified completed current-head review evidence can support automatic admission.
